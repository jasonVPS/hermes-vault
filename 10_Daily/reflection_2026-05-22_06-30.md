# Reflection — 2026-05-22 06:30

- **hermes-vault-sync is genuinely failing** with `Permission denied (publickey)` on push, blocking 4 untracked notes from syncing (including the 06:20 reflection and today’s health-check). This is not an intentional exit(1); it is a broken SSH-key path in the cron environment.
- **Root cause:** The Git remote uses `git@github.com` which resolves to the `id_ed25519` key in `~/.ssh/config` (not the `id_ed25519_vault` key that has repo access). Hermes cron env sets `$HOME=/opt/data/home`, but the minimal env may still fail to map the SSH alias correctly.
- **Action:** Update `vault-sync.sh` to `export GIT_SSH_COMMAND="ssh -i /opt/data/home/.ssh/id_ed25519_vault"` before `git push`, or switch the remote to the `github-vault` alias. Also verify `github.com` host key is accepted in cron env (`StrictHostKeyChecking no` is already set for `github.com` block but not for `github-vault`).
