# Background Cognition — 2026-05-21 07:50

## Observations
- **3 jobs show `last_status: error`** in `jobs.json`:
  - `Vault Graph` — intentional exit(1) signalling 219 broken links, 2 orphans.
  - `Metrics Report` — intentional exit(1) signalling 7 job errors.
  - `Daily Health Check` — intentional exit(1) because it found the above two.
- **Logs**: gateway warnings are from earlier user sessions (execute_code f-string escape, patch denied, security scan), not cron failures.
- **Vault git**: clean, 0 ahead/0 behind.

## Insight
The `Daily Health Check` treats every `last_status: error` as a critical failure, causing it to exit 1 when it sees the *intentional* exit(1)s from `vault-graph.py` and `metrics.py`. This is the "crying wolf" loop described in the skill. The health-check should inspect `last_error` content to distinguish structured anomaly reports from actual crashes.

## Action
- Update `daily-health-check.py` to parse `last_error` text: if it matches the known intentional-exit patterns (e.g. starts with `Graph JSON:` or `Report:` and contains `Broken:` / `Notes:` metrics), treat it as `info` rather than `critical`.
- Consider switching anomaly-reporting scripts from exit(1) to exit(0) with explicit stdout warnings, so `jobs.json` stays clean while still delivering readable reports.
